Replay State Digest Sample
==========================

This file demonstrates the digest computation for replay verification.

1. SHA-256 Hash of Replay State
-------------------------------

Input file: replay_state.json (see appendix/replay_cli.md)

Command:
    sha256sum replay_state.json

Output:
    a3f2c8d9e1b4f7a2c5d8e3f1a4b7c2d5e8f1a3b6c9d2e5f8a1b4c7d0e3f6a9b2  replay_state.json


2. Merkle Root of Transaction Hashes
------------------------------------

For a ledger with 2 transactions, the Merkle tree is:

                    [Root]
                   /      \
             [H(tx1)]    [H(tx2)]

Command (conceptual):
    ./replay_cli merkle-root --events events.jsonl

Output:
    Merkle Root: b4c7d0e3f6a9b2c5e8f1a4d7c0e3f6a9b2c5e8f1a4d7c0e3f6a9b2c5e8f1a4d7

Computation:
    tx1_hash = SHA256(tx1) = a3f2c8d9e1b4f7a2c5d8e3f1a4b7c2d5e8f1a3b6c9d2e5f8a1b4c7d0e3f6a9b2
    tx2_hash = SHA256(tx2) = b4c7d0e3f6a9b2c5e8f1a4d7c0e3f6a9b2c5e8f1a4d7c0e3f6a9b2c5e8f1a4d7
    root = SHA256(tx1_hash || tx2_hash)


3. Hash Chain Verification
--------------------------

The hash chain links each transaction to its predecessor:

    tx[0].prev_hash = 0x0000...0000 (genesis)
    tx[1].prev_hash = SHA256(tx[0])
    tx[2].prev_hash = SHA256(tx[1])
    ...

Command:
    ./replay_cli verify --state replay_state.json --events events.jsonl

Output:
    {
      "status": "VALID",
      "entries_verified": 45892,
      "hash_chain_intact": true,
      "final_hash": "a3f2c8d9e1b4f7a2c5d8e3f1a4b7c2d5e8f1a3b6c9d2e5f8a1b4c7d0e3f6a9",
      "verification_time_ms": 1523
    }


4. Reproducibility Guarantee
----------------------------

To verify determinism, replay the same events twice and compare digests:

    ./replay_cli replay --from "2026-01-01" --to "2026-01-31" --out state1.json
    ./replay_cli replay --from "2026-01-01" --to "2026-01-31" --out state2.json
    
    sha256sum state1.json state2.json

Expected:
    a3f2c8d9e1b4f7a2...  state1.json
    a3f2c8d9e1b4f7a2...  state2.json
    
    (Hashes MUST be identical)
